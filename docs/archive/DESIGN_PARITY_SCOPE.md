# Design Parity Scope — Web vs Mobile

Read-only investigation, no code changed. Compares mobile's CURRENT screens against web's CURRENT (HEAD) design, screen by screen, to answer: which mobile screens still look like the old app that predates web's redesign wave (late Aug – early Sep 2026)?

---

## 1. Design token / shared chrome verdict

**The base tokens are not the problem. Adoption is inconsistent screen-by-screen — the app is a patchwork of two visual eras.**

- **Colors match exactly.** `v1portal-mobile/constants/Colors.ts` `DARK_THEME` was copied 1:1 from web's `app/globals.css` `:root` block: `background:#1d1f23`=`--bg`, `surface:#121212`=`--surface`, `surfaceAlt:#303238`=`--surface2`, `border:rgba(255,255,255,0.09)`=`--border`, `text:#e8e9ea`=`--text`, `success:#71ff7e`=`--green`. All exact matches.
- **Brand gradient matches exactly.** Mobile's `GRADIENT` constant = `['#82008F','#C0007A','#EA0C5F','#FF5341','#FF8820','#F6BA00']`, identical to web's `lib/roleDestinations.ts` `BRAND_GRADIENT_STOPS`. Mobile even pre-built `SCORE_GRADIENT`, `TIER_BARS`, and `scoreNumColor()` helpers specifically to mirror web's `ScoreAnimator` — but **these sit unused**; `components/ScoreAnimator.tsx` on mobile doesn't call them (see Results row below).
- **Fonts are registered correctly but applied inconsistently.** `v1portal-mobile/constants/Fonts.ts` (`FontFamily.headline` = Big Shoulders Display, `.body` = Archivo, `.mono` = JetBrains Mono) correctly mirrors web's *newest* design-system fonts — those three are exactly what web's rebuilt `/signup` wizard (`app/(auth)/auth.css` `.signup-*` classes) and its other 2026-08/09 redesigns use. All three font families are properly loaded via `useFonts()` in `app/_layout.tsx`. The problem: a whole cluster of mobile screens (see table) still specify **no `fontFamily` at all**, so they silently render in the OS system font (San Francisco), which looks like neither web's old system (DM Sans/Inter/Space Grotesk) nor its new one (Big Shoulders/Archivo/JetBrains Mono).
- **Two competing gradients, on both platforms.** Web itself still has an old 2-stop red→purple gradient (`--gradient-btn: linear-gradient(135deg, #ff0000, #aa00ff)`) used on older buttons/badges, alongside the new locked 6-stop `BRAND_GRADIENT_STOPS` used only on the new signup wizard's final CTA, coach dashboard/search accents, and coach setup's progress bar. Mobile's shared `components/AuthButton.tsx` and `components/GradientButton.tsx` both hardcode the **old** `['#ff0000','#aa00ff']` pair, not the newer `GRADIENT` constant that already sits in `Colors.ts` — consistent with web's own older screens, but stale relative to web's newest ones.
- **Net effect:** roughly half of mobile's screens (dashboard home, Results, all coach screens, match/swipe, messages, profile) have been migrated to the new type system and correctly reuse `GRADIENT`. The other half (all of auth, onboarding, gameplan, edit-profile, analytics, calendar, coach-setup's native shell) were never touched and still render in default system font with ad hoc flat colors. This is exactly why Wes's spot-check of signup/onboarding read as "old design" — those happen to be 2 of the ~9 screens still on the old system.

## 3. Prioritized rebuild list

Ranked by user-facing impact first (every user hits auth once; onboarding is the direct complaint), then by frequency of use.

1. **Onboarding (`app/onboarding.tsx`)** — **Large.** Wrong paradigm, not just wrong style: replace the 12-slide pre-app carousel with something in the spirit of web's live spotlight tour (`OnboardingTour.tsx` equivalent — highlight real dashboard elements post-signup) or, at minimum, restyle the carousel onto the new type system/gradient if the carousel is being kept intentionally for mobile. Needs a product decision, not just a reskin.
2. **Signup (`app/(auth)/signup.tsx`)** — **Large.** Full restructure: single scrolling form → 4-step sequential wizard (Name/Email/Password/Finish) matching `app/(auth)/signup/page.tsx`, black background, Big Shoulders/Archivo/JetBrains Mono, gradient-only-on-final-CTA rule, plus a genuinely separate role-selection screen mirroring `/signup/role`'s tile grid.
3. **Athlete Analytics (`app/(tabs)/analytics.tsx`)** — **Medium.** No brand gradient hero, no fonts, ad hoc colors — needs the purple-gradient hero stat card and font/token pass.
4. **Athlete Calendar (`app/(tabs)/calendar.tsx`)** — **Small–medium.** Content is already correct; needs the font pass and the pill-shaped gradient CTA button.
5. **Coach dashboard compliance card (`app/(coach)/index.tsx`)** — **Small.** Swap the bordered neutral card for the bold status-banner treatment (with pulsing urgency indicator) that web shipped yesterday — a scoped, self-contained fix.
6. **Athlete Gameplan (`app/(tabs)/gameplan/*`)** — **Medium.** Font pass + swap flat 14px cards/old gradient for pill-shaped brand-gradient buttons; step-list structure itself doesn't need to change.
7. **Athlete Edit Profile (`app/(tabs)/edit-profile.tsx`)** — **Small.** Gradient/pill language already correct; just needs the font pass on labels/titles.
8. **Athlete dashboard home (`app/(tabs)/index.tsx`)** — **Small–medium.** Add the missing "Top Fit Programs" section, give the gameplan card the bento/hero treatment web gives it, and swap the 2-stop score gradient for the real 6-stop sweep.
9. **Results screen `ScoreAnimator` (`components/ScoreAnimator.tsx`)** — **Small, high-leverage.** The helpers it needs (`SCORE_GRADIENT`, `TIER_BARS`, `scoreNumColor()`) already exist unused in `Colors.ts` — this is a drop-in fix, not new design work: gradient border, animated blue→cyan→green number, 5-segment tier strip.
10. **Auth basics (login/forgot-password/reset-password)** — **Small, low-effort but wide reach.** Just a font-family pass (DM Sans/Inter equivalents) since web itself never redesigned these; not urgent but cheap.
11. **Shared chrome — `AuthButton`/`GradientButton`/`AppDrawer` font & gradient pass** — **Small.** Swap the old 2-stop gradient for the `GRADIENT` constant where the newer brand sweep is intended, and add `FontFamily` to `AppDrawer.tsx`. Fixing this once cleans up several screens at once since these are shared components.

**Not on the list (already fine or non-issues):** Coach setup (deliberately a WebView, matches web by construction), coach search/compliance/recruiting/pipeline/profile-edit (already show the correct adoption signals from tandem builds), swipe/match deck (already migrated), base color/gradient token values (already exact matches — the token *values* were never the problem, only their inconsistent application).
